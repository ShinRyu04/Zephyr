fix(ai)!: Skills di UI akhirnya tersambung ke file, bukan localStorage

Ini bug intinya: backend skills SUDAH lengkap dan SUDAH tersambung ke
prompt - skills.rs menelusuri <workspace>/.zephyr/skills/ dan folder
data Zephyr, lalu agentContext() menyuntikkan daftarnya ke system
prompt. Tapi UI-nya menulis ke agentExtrasStore (localStorage), jadi:

  UI -> localStorage -> MATI DI SITU
  disk -> agentContext -> prompt -> agent

Skill yang dibuat di panel muncul sebagai baris, dan agent tidak pernah
tahu skill itu ada. Tombolnya bekerja, hasilnya tidak.

- skillsStore.ts baru: baca/tulis lewat backend, bukan kunci browser.
  Tidak ada penulisan optimistis - skill_write mengembalikan path, lalu
  daftar dibaca ulang, karena baris optimistis akan menampilkan skill
  yang file-nya gagal ditulis.
- AgcSections: Skills jadi ringkasan + editor. Dulu SETIAP baris adalah
  form, jadi sepuluh skill merender sepuluh textarea. Sekarang satu
  baris = satu editor, dan hanya baris yang dibuka yang me-mount.
- Hapus pakai konfirmasi dua klik: yang dihapus file sungguhan, bukan
  kunci yang bisa dimuat ulang.
- Galat ditampilkan, tidak ditelan. Menulis skill bisa gagal karena hal
  yang localStorage tidak punya (workspace belum dibuka, izin), dan
  daftar kosong akan terbaca sebagai "tidak punya skill".
- skills dihapus dari agentExtrasStore supaya tidak ada dua daftar yang
  bisa berbeda pendapat. Header-nya diperbarui: Hooks tetap di sana dan
  ditandai jelas BELUM ADA EXECUTOR.
- skill_read mengembalikan BODY saja. Sebelumnya file mentah termasuk
  frontmatter, jadi field "Instructions" berisi header ---, dan
  menyimpannya lagi akan menyusun frontmatter kedua di dalam body.
  tulis_skill sudah membuang blok depan; sekarang keduanya sepakat.
- Export bundle di Migrations membaca skills dari disk juga.
